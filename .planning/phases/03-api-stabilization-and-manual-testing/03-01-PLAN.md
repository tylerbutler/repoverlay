  <action>
Convert every `pub` keyword to `pub(crate)` in the 14 source modules listed above. This includes:
- `pub fn` → `pub(crate) fn`
- `pub struct` → `pub(crate) struct`
- `pub enum` → `pub(crate) enum`
- `pub const` → `pub(crate) const`
- `pub trait` → `pub(crate) trait`
- `pub type` → `pub(crate) type`
- `pub use` → `pub(crate) use` (re-exports in lib.rs if any)
- Struct fields: `pub field_name:` → `pub(crate) field_name:` when the containing struct becomes pub(crate)

**Modules to convert (all `pub` → `pub(crate)`):**
1. state.rs (27 items: consts, enums, structs, trait, functions + struct fields)
2. config.rs (16 items: structs, consts, functions + struct fields)
3. detection.rs (12 items: enums, functions, consts)
4. selection.rs (9 items: types, functions)
5. overlay_repo.rs (6 items: struct, functions)
6. json_merge.rs (5 items: types, functions)
7. cache.rs (5 items: structs, functions)
8. upstream.rs (4 items: types)
9. github.rs (3 items: types)
10. sources.rs (2 items: types)
11. fuzzy.rs (2 items: functions)
12. reference.rs (1 item: enum)
13. overlay_name.rs (1 item: struct/newtype)
14. cli.rs (1 item: `pub fn run()` → `pub(crate) fn run()`)

**DO NOT convert:**
- `src/lib.rs` `pub fn run()` — this MUST stay `pub` (called from main.rs as `repoverlay::run()`)
- `src/testutil.rs` — already `#[cfg(test)]` gated, leave its pub items as-is
- `src/main.rs` — binary entry point, not a library module

**Process for each module:**
1. Open the file
2. Replace all `pub ` at item level with `pub(crate) `
3. Also replace `pub ` on struct fields with `pub(crate) `
4. Be careful NOT to change `pub(crate)` items that already exist (some modules may have a few)
5. Be careful NOT to change strings or comments containing "pub"

**After ALL modules are converted, run:**
```bash
cargo check 2>&1
```

If cargo check fails with visibility errors, fix them (likely a missed re-export or cross-module reference). The only expected failure pattern would be if a re-export in lib.rs needs to stay pub for testutil access — but since testutil is #[cfg(test)], this should not be an issue.

**Then run:**
```bash
cargo test 2>&1
```

If tests fail with visibility errors, investigate. Integration tests (tests/cli.rs) use process-level testing and should not be affected. Unit tests within src/ modules use crate-internal access and should work fine with pub(crate).

**API-02 note:** Do NOT add `#[non_exhaustive]` anywhere. This is explicitly skipped per user decision (binary-only, no external consumers).
